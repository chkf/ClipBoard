## Context

产品和交互约定见四份功能规格。主程序与输入法由系统分别启动，任一进程可能在读取粘贴板、处理图片或提交事务时被挂起。

## Goals / Non-Goals

两个入口复用同一套捕获和持久化实现。键盘先显示已保存的摘要，用户点选记录时才读取完整内容。交付范围以 PRD 为准。

## Decisions

- App Group 内的 SQLite 数据库存放设置、变化状态、历史元数据和独立的内容表。原图和缩略图作为 BLOB 随记录事务提交或级联删除，避免文件系统与数据库分别提交时产生孤立文件。数据库目录启用 iOS 文件保护并排除备份。列表只分页查询元数据，缩略图按需读取。
- 用完整 UTF-8 字节识别文本；对图片的有向像素分块计算摘要，另存原始图片数据，以便重新复制原格式。使用 Image I/O 生成缩略图。
- 把系统启动时间、粘贴板变化计数与最近内容摘要一起持久化。采样与提交之间再次核对变化计数和已处理状态。不可比较的计数先匹配内容。删除、清空及过期清理均保留此状态。
- SwiftUI 实现原生导航、列表、预览与设置。UIInputViewController 承载键盘，使用系统输入代理插入文本及切换键盘。仅在入口活动时观察通知并轮询变化计数以补足跨进程通知。
- GitHub Actions 使用 Xcode 26、iOS 26 模拟器和真机 SDK。从发布标签生成可重签 IPA，验证嵌入扩展、架构、版本、两个签名的 App Group，随 Release 提供 SHA-256 校验文件。

## Risks / Trade-offs

- 系统粘贴授权或完全访问受限 → 显示权限说明，继续提供当前可用的历史操作。
- 并发捕获、进程中断 → SQLite 写事务串行化，记录和媒体同生共灭，忙等待放在存储 actor 上。
- 图片解码内存开销 → 摘要分块计算，列表仅使用小缩略图；读取失败时放弃本次捕获并保留历史。
- 真机安装依赖设备签名 → 按用户选择提供包含原始权限的可重签包，安装方为两个目标配置同一个已注册的 App Group。
